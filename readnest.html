A reading log that stays on your phone

Readnest

Your shelf, your notes, and your reading plans — stored on your phone.

Readnest is a reading log built with Flutter. Everything lives in a SQLite database on your own phone — no sign-up, no network calls, no server. Import an existing shelf from WeRead, Goodreads, a CSV file, or a photo of your bookshelf.

01What it does

Eight ways to add a book, one shelf to keep them

Multi-source import

Type the book in by hand, photograph a screenshot or the physical shelf and let ML Kit read it, pull a WeRead shelf across, sync how far you have got, or import from CSV, Notion, Goodreads, Open Library, and Google Books. Whichever way it arrives, it lands on the same shelf.

One data model

Every source is converted into the same Book record before it is stored. Anything a source system wants to keep that Readnest has no field for goes into an extra{} map, so a later import can still read it back.

Deduplication

Two imports of the same book become one record. ISBN decides when it is there; otherwise Readnest falls back to title plus first author. Only blank fields are filled in, so a rating or summary you typed yourself is never overwritten.

Category unification

WeRead calls a shelf Bestsellers or Growth; Goodreads calls the same shelf Self Help. A table of 127 aliases maps names like those onto one list of 20 categories, so a single subject does not show up as two separate slices in your statistics.

Reading plans

A daily plan is a repeating task, not a one-off. Tick today and it comes back tomorrow; the plan is only archived when you decide the whole thing is finished. Reminders are scheduled on the device, so they arrive without a network connection.

Reading statistics

Reading status, categories, monthly reading, ratings, progress, and where the books came from — seven charts you can switch off individually in the display settings. Reading time and active days are left out on purpose: Readnest cannot actually measure them, and a made-up number is worse than an honest blank.

Reading profile

A bubble chart of the categories you actually read, plus personality tags you can add, edit, or delete yourself. Both can be exported as an image — send it to someone, or keep it in your photo album.

AI reading report

You pick the model. It receives statistics Readnest has already worked out locally — counts and percentages, never a book title or a line of your notes — and it is told not to invent numbers it was not given. Yearly and monthly reports are kept so you can read them again, in five voices or one of your own.

03Privacy & offline

Your books never leave your phone

Local-first here is not a slogan but an implementation detail: a SQLite file on your own device.

Readnest has no backend. There is no account to create, no API key to configure for the core features, no cloud sync to keep running, and no server that could be asked to hand anything over. The trade-off is honest: if you lose the phone, you lose the library with it.

  • Local only

    Books, notes, and reading logs live in a SQLite database on the device. No account, no server, no cloud sync.

  • The AI sees numbers, not text

    A report uploads aggregated statistics only — no book titles, no note text. The model cannot invent figures it was not given, and the LLM key is yours to supply.

  • Works offline

    Note-taking, OCR, and every chart work in airplane mode. ML Kit recognises text on the device, so no image is ever uploaded.

05Questions

Things you probably want to ask

Q1Is my data uploaded anywhere?

No, and that is deliberate. Your books, notes, and reading plans live in a SQLite file on your phone. There is no backend to sync with and no account to log into. If you want a backup, copy that file.

Q2Do I need to register an account?

No. There is no sign-up screen and nothing to configure before you can start using it. Install the APK, open it, add a book.

Q3When is the iOS version coming?

There isn't one yet. It is a single Flutter codebase that compiles for both platforms, but building for iOS needs a Mac, which I do not have. The repo does include a codemagic.yaml, which is the usual way to sign and ship an iOS build from a cloud Mac — so if you have access to one, the source is ready to go.

Q4How is this different from WeRead?

WeRead is where you read; Readnest is where you keep the record. You can bring your WeRead shelf across, and once it is here the books live in your phone's own database — your ratings and notes included. Readnest does not talk to WeRead on your behalf after the import.

Q5Does the AI report see my books?

Only the numbers, never the text. Before a prompt is sent, Readnest turns your reading data into a summary of counts and percentages — no titles, no note text. You supply the API key for whichever model you want to use, and it never passes through Readnest because there is no Readnest server.
