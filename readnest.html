Readnest

A bookshelf that lives on your phone.

Built with Flutter and SQLite. Every book, every note, and every reading plan stays inside your phone. No account, no server, no cloud sync. Bring in a WeRead shelf, a Goodreads CSV, a Notion export, or a photo of your actual bookshelf — eight ways in, one bookshelf out.

01Feature set

What you get

Multi-source import

Eight ways in — manual entry, shelf-screenshot OCR, shelf-photo OCR, WeRead shelf sync, reading-progress sync, CSV / Notion import, Goodreads CSV, and Open Library / Google Books search. They all land on one bookshelf.

One data model

Every source collapses into the same Book schema. A single extra{} map carries whatever a source system stores — zero-loss migration.

Deduplication

ISBN wins, then title + first author falls back. Fields only fill gaps — your hand-entered ratings and summaries are never overwritten.

Category unification

A 127-alias mapping folds WeRead's own categories into a controlled 20-term vocabulary, so the same idea never splits into two labels in your stats.

Reading plans

Daily plans are recurring tasks — mark done today, back on the list tomorrow. Only when the whole plan closes does it archive. Local notifications, no cloud.

Reading statistics

Status split, category distribution, monthly reading, rating spread, in-progress progress, and source platform share — seven charts, each one toggleable in display settings. Reading duration and active days are deliberately absent: the app has no way to measure them, and a fabricated number is worse than a missing one.

Reading profile

A bubble plot of what you actually read, plus personality tags you can add, edit, or delete. Both export as an image — share it, or save it to your photo album.

AI reading report

Aggregated, pre-computed stats go to a large model you choose; the model never sees your book titles or note text, and it never invents numbers. Annual and monthly reports, archived so you can reread them, in five voices — or your own.

03Privacy & offline

Your books, your phone, no questions asked.

Local-first isn't a slogan. It's the actual architecture — SQLite on disk, on your device.

Readnest has no backend. There is no account to sign up for, no API key to configure for core features, no cloud sync to keep, and no server to subpoena. If your phone is lost, your library is lost with it. That is the point.

  • Local only

    Books, notes, and reading logs live in a local SQLite database. No account, no server, no cloud sync.

  • AI that respects your text

    Reading reports upload only aggregated statistics — never book titles, never note text. The model can't invent numbers it wasn't given, and the LLM key stays yours.

  • Offline by design

    Reading, OCR, and every chart work with the airplane mode switch on. ML Kit does text recognition on-device; no image ever leaves the phone.

05Questions

Things you probably want to ask

Q1Does it sync my data to a server?

No — not by design. Readnest is strictly local-first: your books, notes, and reading plans live in a SQLite file on your device. There is no backend, no login, no cloud sync. If you want to back up your library, copy the local SQLite file — that's it.

Q2Do I need an account?

No. The whole point is that you don't. There is no login screen, no email field, no API key you have to configure for core features. Install the APK, open the app, that's the sign-up.

Q3When will iOS be out?

Not yet on the App Store. The codebase is one Flutter project that compiles for both platforms, but the iOS build needs a Mac runner I don't own. There is a codemagic.yaml in the repo that would sign and ship the iOS build through Codemagic's cloud — if you run into it first, the source is already ready. See the repo's iOS section.

Q4How is this different from WeRead?

WeRead is a reader with a massive ecosystem. Readnest is the mirror you own. You import your WeRead library into Readnest via the official Agent gateway — the books stay in your phone's SQLite, the ratings and notes stay yours, and Readnest never phones home on your behalf.

Q5Does the AI report see my books?

Only the statistics — not the text. Before any prompt is sent to the model, Readnest aggregates your local reading data into an anonymous summary (counts, distributions, no titles, no note text). You bring your own LLM key, and the key never touches Readnest's servers because there are none.
